# Speculative Rollback Architecture, RAT Checkpoint Recovery, and ROB State Flushing

## The Branch Misprediction Penalty and Speculative State Pollution

In a modern out-of-order superscalar processor core, instructions are fetched, decoded, renamed, and dispatched at high speeds—often processing four to eight instructions on every single clock cycle. To keep the deep execution pipeline filled with useful work, the processor's front-end relies heavily on dynamic branch predictors to guess the direction ($1 = \text{Taken}, 0 = \text{Not-Taken}$) and target address of conditional branch instructions long before those branches reach the execution stage.

As a result, an out-of-order processor spends most of its operational life executing instructions **speculatively**.

At any given moment, up to 128 or 256 in-flight instructions sitting in Reservation Stations, Load-Store Queues, and the Reorder Buffer (ROB) were fetched based on branch predictions that have not been verified yet by the hardware!

Now, consider the physical microarchitectural disaster that occurs when a conditional branch instruction reaches the Execute (EX) stage, evaluates its actual condition in an Arithmetic Logic Unit, and discovers that **the branch predictor made a mistake!**

```text
THE SPECULATIVE STATE POLLUTION CRISIS ON BRANCH MISPREDICTION

 In-Flight Instruction Window (Program Order):
 ┌───────────────────────────┬───────────────────────────┬───────────────────────────┐
 │ Inst 10: BEQ x1, x2, Loop │ Inst 11: ADD x4, x5, x6   │ Inst 12: LW  x7, 0(x4)    │
 │ (Branch Predicted TAKEN)  │ (Speculative Wrong-Path)  │ (Speculative Wrong-Path)  │
 └─────────────┬─────────────┴─────────────┬─────────────┴─────────────┬─────────────┘
               │                           │                           │
               ▼                           ▼                           ▼
        [ Evaluates in EX ]         [ Renamed: x4 -> p42 ]      [ Renamed: x7 -> p43 ]
        [ ACTUAL: NOT-TAKEN! ]      [ Executed in ALU!   ]      [ Dispatched to LSQ! ]
        (MISPREDICTION!)            (WRONG-PATH POLLUTION!)     (WRONG-PATH POLLUTION!)
```

Look closely at the speculative state pollution facing the processor the instant the branch evaluates as **Not-Taken** in the Execute stage:

1. Instruction 10 (`BEQ`) was predicted **Taken** by the front-end branch predictor.
2. The front-end jumped to the loop target address and fetched Instruction 11 (`ADD`) and Instruction 12 (`LW`).
3. During the 12 clock cycles that Instruction 10 spent waiting in a Reservation Station, Instructions 11 and 12 were processed by the front-end:
   * Instruction 11 was renamed, assigned physical register $p42$, allocated a Reorder Buffer entry, and **already executed in an Integer ALU!**
   * Instruction 12 was renamed, assigned physical register $p43$, allocated an LSQ entry, and **dispatched a memory load to the L1 Data Cache!**
4. On Clock Cycle 13, Instruction 10 (`BEQ`) completes execution in the Branch ALU and discovers the truth: **The branch condition was NOT-TAKEN!**

Look at the speculative destruction sitting inside the processor:
* Instructions 11 and 12 belong to the **wrong execution path**! They were never supposed to exist in the real program flow!
* Physical registers $p42$ and $p43$ are currently holding speculative calculation results generated by wrong-path instructions.
* The Register Alias Table (RAT) has been corrupted with wrong-path mappings ($x4 \to p42, x7 \to p43$).
* The Reorder Buffer (ROB), Reservation Stations (RS), and Load-Store Queues (LSQ) are filled with wrong-path instructions.

If the processor cannot purge these wrong-path instructions immediately and restore the exact architectural state that existed *before* the mispredicted branch:
* Physical registers $p42$ and $p43$ will be permanently leaked, eventually starving the Free List.
* The Register Alias Table will route future valid instructions to corrupted physical registers.
* Wrong-path memory loads will pollute the L1 Data Cache and trigger false memory order violations.

How can an out-of-order processor flush hundreds of speculative wrong-path instructions from its execution queues, reclaim leaked physical registers, restore its global branch history, and reset its Register Alias Table to the correct pre-branch state—**all in a single clock cycle without stalling the entire chip?**

To solve this speculative state recovery crisis, microarchitects use **Speculative Rollback Architecture**, **RAT Checkpoint Recovery**, and **ROB State Flushing**.

## Out-of-Order Misprediction Detection and ROB State Flushing

To understand how an out-of-order processor purges wrong-path instructions in silicon, we must examine the formal execution path of a conditional branch instruction inside the Execute (EX) stage.

When a conditional branch instruction (e.g., `BEQ x1, x2, Target`) dispatches from a Reservation Station into a Branch Execution Unit (Branch ALU):

1. **Condition Evaluation**:
   The Branch ALU calculates whether the condition is met (e.g., checks if $x1 == x2$).
   $$\text{Actual\_Taken} = (x1 == x2) \quad ? \quad 1 \quad : \quad 0$$
2. **Target Address Calculation**:
   The Branch AGU calculates the actual branch target memory address:
   $$\text{Actual\_Target} = \text{Branch\_PC} + \text{SignExtend}(\text{Offset})$$
3. **Misprediction Detection Logic**:
   The hardware compares the actual outcome against the predicted direction ($\text{Pred\_Taken}$) and predicted target address ($\text{Pred\_Target}$) provided by the front-end branch predictor when the branch was fetched:

$$
\text{Branch\_Mispredicted} = (\text{Actual\_Taken} \neq \text{Pred\_Taken}) \quad \lor \quad (\text{Actual\_Taken} \quad \land \quad (\text{Actual\_Target} \neq \text{Pred\_Target}))
$$

Where:
* $\text{Branch\_Mispredicted}$ is a 1-bit active-high signal asserted by the Branch ALU in the EX stage.
* $\text{Actual\_Taken} \in \{0, 1\}$ is the resolved branch direction.
* $\text{Pred\_Taken} \in \{0, 1\}$ is the direction guessed by the branch predictor during IF.
* $\text{Actual\_Target}$ is the calculated physical branch target memory address.
* $\text{Pred\_Target}$ is the target address guessed by the Branch Target Buffer (BTB) during IF.

```text
BRANCH MISPREDICTION DETECTION SCHEMATIC (EX STAGE)

 Actual Direction (Actual_Taken) ──┐
 Predicted Dir    (Pred_Taken)   ──┴──►[ 1-Bit Comparator ]──► Dir_Mismatch ──┐
                                                                               ├──► OR Gate ──► Branch_Mispredicted
 Actual Target   (Actual_Target) ──┐                                           │
 Predicted Target (Pred_Target)  ──┴──►[ 32-Bit Comparator]──► Target_Mismatch┘
```

### The Reorder Buffer (ROB) Selective Flushing Algorithm

When $\text{Branch\_Mispredicted} = 1$ asserts in the EX stage, the branch instruction broadcasts its unique Reorder Buffer tag ($\text{Branch\_ROB\_ID}$) over the execution control bus.

Every slot in the circular Reorder Buffer compares its own age ($\text{ROB\_ID}_k$) against $\text{Branch\_ROB\_ID}$:

```text
REORDER BUFFER SELECTIVE STATE FLUSHING

 Reorder Buffer Circular Queue:
 ┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
 │ ROB_00   │ ROB_01   │ ROB_02   │ ROB_03   │ ROB_04   │ ROB_05   │
 │ Inst 8   │ Inst 9   │ BEQ      │ Inst 11  │ Inst 12  │ Inst 13  │
 │ (Older)  │ (Older)  │ (Branch!)│ (Younger)│ (Younger)│ (Younger)│
 └──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
  VALID!      VALID!    MISPREDICT!  FLUSHED!   FLUSHED!   FLUSHED!
  (Keep)      (Keep)    (Corrected)  (Purged!)  (Purged!)  (Purged!)
```

#### The ROB Flushing Condition:
For every slot $k$ in the Reorder Buffer:

$$\text{Flush\_Entry}_k = \text{Branch\_Mispredicted} \quad \land \quad V_{\text{busy},k} \quad \land \quad (\text{ROB\_ID}_k > \text{Branch\_ROB\_ID})$$

Where:
* $\text{ROB\_ID}_k > \text{Branch\_ROB\_ID}$ evaluates whether instruction $k$ is **younger in program order** than the mispredicted branch.

When $\text{Flush\_Entry}_k == 1$:
1. **Purge ROB Slot**: $\text{ROB}[k].V_{\text{busy}} \Leftarrow 0$, clearing the slot immediately.
2. **Reclaim Speculative Physical Register**: The physical register $P_{\text{new},k}$ assigned to instruction $k$ is **canceled** and returned to the Free List FIFO:
   $$\text{Free\_List\_Push}(P_{\text{new},k})$$
3. **Reset ROB Tail Pointer**: The ROB tail pointer is instantly reset to point right after the branch instruction:
   $$\text{tail\_ptr} \Leftarrow (\text{Branch\_ROB\_ID} + 1) \bmod N_{\text{ROB}}$$

Notice what selective flushing achieved:
* All instructions **older** than the branch ($\text{ROB\_ID} < \text{Branch\_ROB\_ID}$) remain completely safe and valid in the ROB!
* All instructions **younger** than the branch ($\text{ROB\_ID} > \text{Branch\_ROB\_ID}$) are purged simultaneously!

## RAT Checkpoint Recovery vs. Sequential ROB Walkback

Flushing the Reorder Buffer purges wrong-path instructions, but what about the **Register Alias Table (RAT)**?

During the 12 clock cycles that wrong-path instructions were being renamed, they updated the active RAT array with corrupted physical register mappings ($x4 \to p42, x7 \to p43$).

To restore the RAT to its exact pre-branch state, computer microarchitects choose between two primary recovery paradigms: **1-Cycle RAT Checkpoint Recovery** and **Sequential ROB Walkback**.

```text
RAT RECOVERY PARADIGMS COMPARISON

 Paradigm 1: Speculative RAT Checkpoint Recovery (1-Cycle Instant Snapshots)
  [ Active RAT Array ] ◄── Restore in 1 Cycle! ── [ Shadow Checkpoint Array [Branch_ID] ]
  * Recovery Time : EXACTLY 1 CLOCK CYCLE!
  * Hardware Cost : Requires shadow SRAM arrays for every in-flight branch.

 Paradigm 2: Sequential ROB Walkback (Slow Iterative Recovery - Zero Shadow Registers)
  [ Active RAT Array ] ◄── Walk Backward Step-by-Step ── [ Reorder Buffer Entries ]
  * Recovery Time : 1 Clock Cycle PER FLUSHED INSTRUCTION (3 to 8 Cycles!).
  * Hardware Cost : ZERO extra shadow registers! Minimal silicon area.
```

---

### Paradigm 1: Speculative RAT Checkpoint Recovery (1-Cycle Instant Snapshots)

In **1-Cycle RAT Checkpoint Recovery**:

1. **Snapshot Creation at Rename (Dispatch Stage)**:
   When a conditional branch instruction enters the Rename stage, it is allocated a unique **Branch Checkpoint ID** (e.g., $\text{Branch\_ID} \in \{0, 1, 2, 3\}$).
   The CPU copies the entire 32-entry active RAT array into a dedicated **Shadow Checkpoint Register Array ($\text{RAT}_{\text{checkpoint}}[\text{Branch\_ID}]$)** in a single clock cycle:

$$\mathbf{RAT}_{\text{checkpoint}}[\text{Branch\_ID}] \Leftarrow \mathbf{RAT}_{\text{active}}$$

2. **Instant Restoration on Misprediction (EX Stage)**:
   When the Branch ALU asserts $\text{Branch\_Mispredicted} = 1$ with $\text{Branch\_ID} = 2$:
   A 32-wide array of 2-to-1 multiplexers copies the shadow checkpoint array directly back into the active RAT:

$$\mathbf{RAT}_{\text{active}} \Leftarrow \mathbf{RAT}_{\text{checkpoint}}[\text{Branch\_ID}]$$

```text
SPECULATIVE RAT CHECKPOINT RESTORATION SCHEMATIC

 Shadow Checkpoint 2 (Saved at Branch Rename)
 [ x0: p0 | x1: p1 | x2: p2 | x4: p4 | x7: p7 ... x31: p31 ]
            │
            ▼ (1-Cycle Multiplexer Array Transfer!)
 Active RAT Array (Corrupted with wrong-path mappings)
 [ x0: p0 | x1: p1 | x2: p2 | x4: p42 | x7: p43 ... x31: p31 ]
            │
            ▼ (RESTORED IN 1 CLOCK CYCLE!)
 Active RAT Array (100% Restored Clean State!)
 [ x0: p0 | x1: p1 | x2: p2 | x4: p4 | x7: p7 ... x31: p31 ]
```

#### Microarchitectural Trade-Offs of Checkpoint Recovery:
* **Recovery Latency**: **Exactly 1 clock cycle!** The front-end can resume renaming correct-path instructions on the very next clock cycle.
* **Silicon Area Overhead**: Storing 4 shadow checkpoints for a 32-entry $\times$ 7-bit RAT requires $4 \times 224 = 896$ additional shadow flip-flops and routing multiplexers.

---

### Paradigm 2: Sequential ROB Walkback (Slow Iterative Recovery)

In **Sequential ROB Walkback**:
The CPU maintains no shadow checkpoint registers.

When a branch misprediction is detected:
1. The front-end renaming engine pauses.
2. The recovery logic reads the Reorder Buffer entries starting from the tail pointer ($\text{tail\_ptr}$) and walks **backward** toward the mispredicted branch ($\text{Branch\_ROB\_ID}$).
3. For every flushed instruction $k$ encountered during the walkback:
   * The recovery logic reads the instruction's architectural destination $rd_k$ and previous physical register tag $P_{\text{old},k}$.
   * The recovery logic restores the active RAT mapping:
     $$\mathbf{RAT}[rd_k] \Leftarrow P_{\text{old},k}$$
   * The fresh physical register $P_{\text{new},k}$ is pushed back onto the Free List.
4. Each step of the walkback takes 1 clock cycle. If 6 wrong-path instructions were flushed, recovery takes **6 full clock cycles**.

```text
RAT RECOVERY PARADIGM MATRIX

 Microarchitectural Feature │ 1-Cycle RAT Checkpoint Recovery │ Sequential ROB Walkback
────────────────────────────┼─────────────────────────────────┼───────────────────────────────
 Recovery Time (Latency)    │ 1 Clock Cycle (Instant!)        │ K Cycles (1 cycle per flushed inst)
 Silicon Area Footprint     │ High (Requires Shadow SRAM)     │ Minimal (Zero Shadow SRAM)
 Front-End Redirect Penalty │ Low (1 Cycle Penalty)           │ High (K Cycles Penalty)
 Common Usage               │ High-Performance Desktop / Server│ Ultra-Low-Power Embedded Cores
```

Because 1-cycle checkpoint recovery minimizes branch misprediction penalties, **all high-performance out-of-order processors (Intel Core, AMD Zen, Apple M-Series, ARM Neoverse) use Speculative RAT Checkpoint Recovery.**

## Speculative Global History Register (GHR) Restoration and PC Steering

Beyond the Reorder Buffer and Register Alias Table, branch misprediction recovery must repair two critical front-end structures: **The Global History Register (GHR)** and **The Program Counter (PC)**.

---

### 1. Speculative GHR Restoration

In the Instruction Fetch (IF) stage, the $m$-bit Global History Register ($GHR$) is speculatively shifted on every predicted branch so that younger branches can index the TAGE or Gshare predictor using fresh global history.

When a branch is mispredicted in the EX stage, the speculative $GHR$ sitting in the fetch engine is corrupted with wrong-path branch history bits!

To repair the $GHR$:
1. At rename time, the pre-branch GHR value was saved into a checkpoint register ($\text{GHR}_{\text{checkpoint}}[\text{Branch\_ID}]$).
2. On misprediction, the speculative GHR is restored from the checkpoint and updated with the **actual, resolved branch direction**:

$$
GHR_{\text{restored}} = \left( \text{GHR}_{\text{checkpoint}}[\text{Branch\_ID}] \ll 1 \right) \quad \mid \quad \text{Actual\_Taken}
$$

The global history register is $100\%$ restored and aligned with the correct execution path in 1 clock cycle!

---

### 2. Program Counter (PC) Steering Redirect

Simultaneously, the branch execution unit calculates the **Correct Target PC**:

$$
PC_{\text{correct}} = (\text{Actual\_Taken}) \quad ? \quad \text{Actual\_Target} \quad : \quad (\text{Branch\_PC} + 4)
$$

The front-end Program Counter multiplexer asserts $PC \Leftarrow PC_{\text{correct}}$, redirecting the instruction fetch engine to fetch fresh, clean instructions from the correct program path starting on the very next clock cycle!

```text
COMPLETE 1-CYCLE SPECULATIVE ROLLBACK OVERVIEW

 EX Stage Branch ALU Asserts Branch_Mispredicted = 1
                      │
 ┌────────────────────┼────────────────────┬────────────────────┐
 │                    │                    │                    │
 ▼                    ▼                    ▼                    ▼
[ ROB Selective ]    [ RAT Checkpoint ]   [ GHR Checkpoint ]   [ PC Redirect ]
[ State Flush   ]    [ 1-Cycle Restore]   [ Restoration    ]   [ PC <= PC_correct ]
(Purge Wrong-Path)   (Active RAT <= Chk)  (GHR <= Correct)     (Fetch Correct Path)
```

### Step-by-Step Derivation

#### Step 1: Calculate Critical Path Delay and Timing Slack

Let us trace the physical critical path through the speculative rollback unit during a branch misprediction cycle:

1. Branch ALU detects misprediction and outputs $\text{Branch\_Mispredicted} = 1$.
2. 8-Entry ROB Selective Flush Comparators ($\text{ROB\_ID}_k > \text{Branch\_ROB\_ID}$): $t_{\text{flush}} = 0.14\text{ ns}$.
3. 32-Entry RAT Checkpoint Restoration MUX Array ($\mathbf{RAT}_{\text{active}} \Leftarrow \mathbf{RAT}_{\text{chk1}}$): $t_{\text{rat\_restore}} = 0.18\text{ ns}$.
4. Free List Physical Tag Reclamation Mask Logic: $t_{\text{reclaim}} = 0.12\text{ ns}$.
5. PC Redirect Register Setup Time: $t_{\text{su}} = 0.14\text{ ns}$.

$$
t_{\text{rollback\_path}} = t_{\text{flush}} + t_{\text{rat\_restore}} + t_{\text{reclaim}} + t_{\text{su}}
$$

$$
t_{\text{rollback\_path}} = 0.14\text{ ns} + 0.18\text{ ns} + 0.12\text{ ns} + 0.14\text{ ns} = \mathbf{0.580 \text{ ns}}
$$

##### Setup Timing Slack ($T_{\text{slack}}$) at $T_{\text{clk}} = 2.00\text{ ns}$ ($500\text{ MHz}$):

$$
T_{\text{slack}} = T_{\text{clk}} - t_{\text{rollback\_path}} = 2.000\text{ ns} - 0.580\text{ ns} = \mathbf{+1.420 \text{ ns} \quad (POSITIVE SLACK!)}
$$

The speculative rollback subsystem evaluates in **$0.580\text{ nanoseconds}$**, closing timing at $500\text{ MHz}$ with $+1.420\text{ ns}$ of positive slack!

---

#### Step 2: Derive Control Boolean Equations

For each ROB slot $k \in \{0 \dots 7\}$ and physical register $p \in \{0 \dots 63\}$:

1. **ROB Entry Selective Flush Mask ($\text{rob\_flush\_mask}[k]$)**:
   $$\text{rob\_flush\_mask}[k] = \text{mispredict} \quad \land \quad V_{\text{busy}}[k] \quad \land \quad (\text{ROB\_ID}[k] > \text{branch\_rob\_id})$$

2. **Physical Register Reclamation Mask ($\text{reclaim\_mask}[p]$)**:
   Physical register $p$ is reclaimed if it was assigned as $P_{\text{new}}$ to ANY flushed ROB entry:
   $$\text{reclaim\_mask}[p] = \bigvee_{k=0}^{7} \left( \text{rob\_flush\_mask}[k] \quad \land \quad (\text{ROB}[k].P_{\text{new}} == p) \right)$$

3. **Active RAT Restoration (`active_rat_restore_en`)**:
   $$\text{active\_rat\_restore\_en} = \text{mispredict}$$

4. **PC Redirect Target Address (`pc_redirect_addr`)**:
   $$\text{pc\_redirect\_addr} = (\text{actual\_taken}) \quad ? \quad \text{actual\_target} \quad : \quad (\text{branch\_pc} + 4)$$

    input  logic        reset_n,

    // EX Stage Branch Resolution Inputs
    input  logic        mispredict,
    input  logic [1:0]  branch_chk_id,    // Checkpoint ID (0..3)
    input  logic [2:0]  branch_rob_id,    // ROB ID of Branch (0..7)
    input  logic [31:0] branch_pc,        // PC of Branch
    input  logic        actual_taken,     // Actual direction
    input  logic [31:0] actual_target,    // Calculated target address

    // ROB State Inputs
    input  logic [ROB_SIZE-1:0] rob_busy_vector,
    input  logic [5:0]          rob_p_new [0:ROB_SIZE-1],

    // RAT Checkpoint Memory Interface
    input  logic [5:0] rat_chk_mem [0:NUM_CHECK-1][0:NUM_ARCH-1],
    output logic [5:0] active_rat_out  [0:NUM_ARCH-1],

    // Subsystem Control Outputs
    output logic [ROB_SIZE-1:0] rob_flush_mask,      // Active-high flush bit per ROB entry
    output logic [NUM_PHYS-1:0] reclaimed_phys_mask, // Active-high mask of freed physical regs
    output logic [31:0]         pc_redirect_addr,    // Redirected PC for Fetch engine
    output logic                active_rat_restore_en// 1 = Active RAT restored from checkpoint
);

    // 1. Calculate ROB Entry Selective Flush Mask
    genvar k;
    generate
        for (k = 0; k < ROB_SIZE; k++) begin : g_rob_flush
            assign rob_flush_mask[k] = mispredict && rob_busy_vector[k] && (3'(k) > branch_rob_id);
        end
    endgenerate

    // 2. Calculate Physical Register Tag Reclamation Mask
    integer p, r;
    always_comb begin
        reclaimed_phys_mask = '0;
        if (mispredict) begin
            for (r = 0; r < ROB_SIZE; r++) begin
                if (rob_flush_mask[r]) begin
                    reclaimed_phys_mask[rob_p_new[r]] = 1'b1; // Mark physical reg freed!
                end
            end
        end
    end

    // 3. PC Steering Redirection Address
    assign pc_redirect_addr = (actual_taken) ? actual_target : (branch_pc + 32'd4);

    // 4. 1-Cycle Active RAT Checkpoint Restoration
    assign active_rat_restore_en = mispredict;

    integer a;
    always_comb begin
        if (mispredict) begin
            for (a = 0; a < NUM_ARCH; a++) begin
                active_rat_out[a] = rat_chk_mem[branch_chk_id][a]; // Restore in 1 cycle!
            end
        end else begin
            for (a = 0; a < NUM_ARCH; a++) begin
                active_rat_out[a] = 6'd0;
            end
        end
    end

endmodule

## Key Output Primitives

This lesson formally delivers the following conceptual primitives to your digital logic engineering toolbox:

* **Speculative Rollback**: The hardware state recovery process that purges all wrong-path speculative instructions, reclaims leaked physical registers, and redirects the Program Counter to the correct execution path when a branch misprediction or hardware exception occurs.
* **RAT Checkpoint Recovery**: A 1-cycle hardware restoration mechanism that uses shadow flip-flop snapshot arrays ($\text{RAT}_{\text{checkpoint}}$) saved at branch rename time to instantly overwrite corrupted active RAT mappings upon branch misprediction detection.
* **ROB State Flushing**: The selective invalidation process where the Reorder Buffer compares the age tags of all in-flight instructions ($\text{ROB\_ID}_k$) against a mispredicted branch tag ($\text{Branch\_ROB\_ID}$), invalidating all younger entries ($\text{ROB\_ID}_k > \text{Branch\_ROB\_ID}$) while preserving older valid instructions.
